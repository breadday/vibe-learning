# TASK-005 구현 결과

## 구현 요약

- `external` 재생 모드에서 iframe과 플레이어 비율 공간을 렌더링하지 않고, 외부 재생 기능을 `외부 재생 도구` 모음으로 축소했다.
- 외부 모드의 핵심 작업인 `학습 구간`과 `개인 메모`를 별도 작업 영역으로 묶었다. 901px 이상에서는 학습 구간이 왼쪽, 개인 메모가 오른쪽인 두 열로 표시되고, 900px 이하에서는 학습 구간 다음 개인 메모 순서의 한 열로 표시된다.
- 520px 이하에서 외부 링크, 위치 입력, 저장 및 모드 전환 조작이 한 열로 줄바꿈되고 최소 44px 이상의 터치 영역을 유지하도록 했다.
- 기존 위치 저장, YouTube 링크, 구간·메모 추가/수정/삭제, 새로고침 지속성, 내장 모드 복귀 동작은 기존 저장 스키마와 핸들러를 그대로 사용했다.
- 설치된 Next.js 16.3.2의 Global CSS, 접근성, Vitest, Playwright 가이드를 확인했다. 이번 변경에는 Next.js API 변경이 필요하지 않았다.

## 실패하거나 실행하지 못한 테스트

- 최종 검증에서 실패하거나 실행하지 못한 테스트는 없다.
- 초기 `npm run test:e2e` 두 번은 5개 테스트 실행 표시 후 Windows에서 Playwright가 직접 시작한 Next.js 개발 서버의 종료가 지연되어 성공 요약과 종료 코드를 얻지 못했다. 해당 실행은 통과로 기록하지 않고 중단했다. 이후 기존 개발 서버 재사용 설정으로 동일 명령을 다시 실행해 `5 passed`와 정상 종료를 확인했다.

## 남은 문제와 위험

- Windows에서 실행 중인 개발 서버가 없는 상태로 Playwright가 서버를 직접 시작하면, 현재 환경과 같은 자식 프로세스 종료 지연이 다시 발생할 가능성이 있다. 테스트 assertion 실패나 애플리케이션 기능 문제는 아니며, 로컬에서 개발 서버를 먼저 실행하면 정상 종료됨을 확인했다.
- 레이아웃 검증은 Chromium의 1280px 및 360px 뷰포트에서 수행했다. Playwright 프로젝트에 포함되지 않은 Firefox와 WebKit은 이번 작업에서 실행하지 않았다.

## 후속 작업이 필요한 항목

- 필수 기능 후속 작업은 없다.
- 필요하면 Windows에서 Playwright가 시작한 Next.js 서버의 종료 지연을 별도 테스트 인프라 작업으로 조사할 수 있다.
- 필요하면 Firefox와 WebKit 프로젝트를 별도 범위에서 추가해 브라우저별 반응형 회귀 검증을 확대할 수 있다.

요청하지 않은 커밋과 배포는 수행하지 않았다.
