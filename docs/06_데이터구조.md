# 데이터 구조

## 저장 방식 요약

| 데이터 | 위치 | 구분 | 사용 상태 |
|---|---|---|---|
| 학습 목록·상태·메모 | 브라우저 `localStorage` | 개인 로컬 데이터 | 현재 사용 |
| JSON 백업 | 사용자 다운로드 파일 | 개인 백업 | 현재 사용 |
| 검수 영상 콘텐츠 | `content/first-video.json` | 저장소 콘텐츠 | 검증됨, 라우트 미연결 |
| 검수 설명 | `content/reviewed/first-video.mdx` | 저장소 콘텐츠 | 라우트 미연결 |

데이터베이스는 사용하지 않습니다.

## 개인 학습 저장소 v1

저장 키는 `vibe-learning:v1`, `schemaVersion`은 `1`입니다.

```ts
type LearningStore = {
  schemaVersion: 1;
  videos: LearningVideo[];
  lastOpenedVideoId: string | null;
};

type LearningVideo = {
  youtubeId: string;
  title: string;
  normalizedUrl: string;
  status: "not-started" | "in-progress" | "completed";
  playbackSeconds: number;
  notes: LearningNote[];
  createdAt: string;
  updatedAt: string;
};

type LearningNote = {
  id: string;
  timestampSeconds: number;
  text: string;
  createdAt: string;
  updatedAt: string;
};
```

한 영상의 메모는 최대 500개이며 각 메모는 1~2,000자입니다. 영상 ID와 정규화 URL은 일치해야 하고 영상 및 메모 ID는 중복될 수 없습니다. `lastOpenedVideoId`는 목록에 실제로 있는 영상이어야 합니다.

손상되거나 맞지 않는 저장값은 빈 v1 저장소로 복구합니다. 구형 v1 영상에 `playbackSeconds` 또는 `notes`가 없으면 각각 `0`, 빈 배열을 적용합니다.

## 검수 콘텐츠 v1

`content/first-video.json`도 `schemaVersion: 1`이지만 개인 학습 저장소와는 별도 형식입니다. 영상 메타데이터, 검수·최신성 상태, 영상 구간, 실습 단계, 복사 블록, 개념, 경고, 출처, TODO를 포함합니다.

구간은 시작보다 종료가 늦어야 하고 서로 겹치거나 영상 길이를 넘을 수 없습니다. 필수 구간은 최대 5개, 선택 구간은 최대 3개입니다. `reviewed` 콘텐츠는 영상 메타데이터와 최신성 확인일이 모두 있어야 하며 TODO를 남길 수 없습니다.

이 구조는 Zod로 검증하고 Draft 2020-12 JSON Schema로 변환합니다. 세부 계약은 [[12_content_json_schema]]를 참고합니다.
