# TASK-007: 자동 제목 재선택 및 상태 안내 보정

## 목표

TASK-006의 YouTube 제목 자동 입력 기능에서 영상 주소를 바꿨다가 이전 영상으로 돌아왔을 때 제목이 비는 문제와, 사용자 제목을 유지했는데도 자동 입력 성공으로 안내하는 문제를 수정한다.

- 유효한 영상 주소를 선택할 때마다 해당 영상의 자동 제목을 안정적으로 제공한다.
- 사용자가 직접 작성한 제목을 최우선으로 보존한다.
- 화면에 표시되는 조회 상태가 실제로 수행된 동작과 일치하게 한다.

## 현재 문제

### 1. 조회했던 영상으로 돌아오면 제목이 비어 있음

`components/AddVideoForm.tsx`는 조회를 시작한 영상 ID를 `attemptedVideoIdsRef`의 `Set`에 계속 보관한다.

1. 영상 A의 제목을 자동 입력한다.
2. 영상 B로 주소를 변경하면 A의 자동 제목을 지우고 B의 제목을 조회한다.
3. 다시 영상 A 주소를 입력하면 A가 이미 시도한 ID이므로 조회를 생략한다.
4. B의 자동 제목은 URL 변경 과정에서 삭제되므로 제목 입력란이 빈 상태로 남는다.

따라서 “유효한 YouTube 주소를 입력하면 제목을 자동 입력한다”는 TASK-006 완료조건이 같은 폼 안의 A → B → A 흐름에서는 성립하지 않는다.

### 2. 사용자 제목에도 잘못된 성공 안내가 표시됨

제목 조회 중 사용자가 직접 제목을 입력하면 API 응답은 사용자 값을 덮어쓰지 않는다. 그러나 응답 처리 마지막에 조회 상태를 무조건 `success`로 변경해 다음 문구를 표시한다.

```text
영상 제목을 자동으로 입력했습니다. 필요하면 수정할 수 있습니다.
```

실제로는 자동 제목을 입력하지 않았으므로 사용자와 화면 읽기 도구에 잘못된 상태를 전달한다.

## 요구사항

### 1. 영상 재선택 동작

- A → B → A처럼 이전에 조회한 유효한 영상 ID를 다시 선택해도 A의 제목이 제목 입력란에 표시되어야 한다.
- 성공한 자동 제목은 컴포넌트가 유지되는 동안 영상 ID별로 캐시해 재사용하는 방식을 우선한다.
- 캐시는 브라우저 메모리에만 두고 `localStorage`, 저장 스키마, 백업 데이터에 추가하지 않는다.
- 캐시가 있는 영상으로 돌아오면 외부 API를 다시 호출하지 않고 캐시 제목을 사용할 수 있다.
- 캐시에 제목이 없는 영상은 기존 300ms 디바운스 후 내부 제목 API를 호출한다.
- URL 변경 시 진행 중인 이전 요청은 기존처럼 취소하거나 요청 순번으로 무시한다.
- 실패한 조회를 성공 캐시에 저장하지 않는다.
- 실패했던 영상에서 다른 영상으로 이동한 뒤 다시 돌아온 경우에는 새 조회를 시도할 수 있어야 한다. 같은 선택 상태에서 자동 재시도를 반복하지는 않는다.
- React Strict Mode의 effect 재실행이나 일반 리렌더링으로 동일 영상에 중복 요청이 발생하지 않아야 한다.

### 2. 제목 출처와 상태 안내

- API 응답으로 실제 제목 입력값을 변경한 경우에만 `success` 상태와 `영상 제목을 자동으로 입력했습니다.` 안내를 표시한다.
- 조회 중 사용자가 제목을 직접 입력했다면 응답 제목을 캐시할 수는 있지만 사용자 입력값을 변경하지 않는다.
- 사용자 제목을 유지한 경우 자동 입력 성공 문구를 표시하지 않는다. 상태는 `idle`로 되돌리거나 `직접 입력한 제목을 유지했습니다.`처럼 실제 동작과 일치하는 별도 상태로 표현한다.
- 사용자 제목을 유지하는 상태를 추가한다면 화면 읽기 도구가 인식할 수 있는 `role="status"`와 입력의 `aria-describedby` 연결을 유지한다.
- URL 변경 시 자동 제목만 교체·삭제하고 사용자가 직접 입력한 제목은 계속 보존한다.
- 자동 제목 캐시를 적용하더라도 사용자 제목이 캐시 제목으로 덮어써지지 않아야 한다.

### 3. 오류와 기존 흐름 유지

- API 실패 시 기존 `제목을 자동으로 가져오지 못했습니다. 직접 입력해 주세요.` 안내와 수동 등록 폴백을 유지한다.
- 자동 제목, 사용자 제목, 빈 제목에 따른 `학습에 추가` 버튼 활성화 조건을 변경하지 않는다.
- 저장 오류와 제목 조회 상태는 계속 독립적으로 표시한다.
- 중복 영상 처리, 저장, 상세 이동, 목록 표시, 백업·복원 동작을 변경하지 않는다.

## 제약사항

- `app/api/youtube-title/route.ts`, YouTube Data API 요청 형식, `YOUTUBE_API_KEY` 처리와 상태 코드 계약은 변경하지 않는다.
- `LearningVideo`와 `vibe-learning:v1` 스키마를 변경하지 않는다.
- 새로운 npm 패키지, 서버 저장, 데이터베이스, 로그인, 영구 메타데이터 캐시를 추가하지 않는다.
- API 키나 실제 YouTube 응답을 저장소에 추가하지 않는다.
- TASK-005와 TASK-006의 기존 변경을 되돌리지 않는다.
- 구현 전에 현재 `AddVideoForm.tsx`와 테스트를 읽고 React effect 수명과 요청 취소 흐름을 파악한다.

## 테스트 조건

### 컴포넌트 테스트

- A 조회 성공 후 B 조회 성공, 다시 A 입력 시 A 제목 복원
- A → B → A에서 A의 내부 제목 API 호출 횟수가 1회인지 확인
- A 조회 실패 후 B로 이동했다 A로 돌아오면 A를 다시 요청
- 동일 videoId로 리렌더링해도 요청 1회 유지
- 조회 대기 중 사용자 제목 입력 후 응답 완료 시 사용자 제목 유지
- 위 사용자 우선 흐름에서 자동 입력 성공 문구가 표시되지 않음
- 자동 제목을 실제로 적용한 경우에만 성공 문구 표시
- 캐시된 자동 제목이 사용자 제목을 덮어쓰지 않음
- API 실패 안내와 수동 저장 회귀
- URL 변경 뒤 오래된 응답 무시 및 컴포넌트 해제 시 요청 취소 회귀

### E2E 테스트

- 내부 `/api/youtube-title` 요청을 가로채 영상 A와 B에 서로 다른 제목을 반환한다.
- 같은 홈 폼에서 A → B → A 순서로 주소를 입력하고 각 단계의 제목이 올바른지 확인한다.
- A 재선택 시 A 요청이 추가로 발생하지 않는지 확인한다.
- 지연된 자동 응답 전에 사용자 제목을 입력하고, 응답 후에도 사용자 제목과 정확한 상태 안내가 유지되는지 확인한다.
- 실제 Google API와 실제 키에 의존하지 않는다.
