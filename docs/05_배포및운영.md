# 배포 및 운영

## 현재 확인된 자동화

`.github/workflows/ci.yml`의 GitHub Actions `Verify` 워크플로는 Pull Request와 `main` 브랜치 push 때 다음을 실행합니다.

```text
checkout → Node.js 24 → npm ci → lint → typecheck → Vitest
→ webpack 프로덕션 빌드 → Playwright Chromium 설치 → E2E 테스트
```

같은 Git ref의 새 실행이 시작되면 이전 실행을 취소하고, 작업 제한 시간은 10분입니다.

## 실제 배포 방식

배포 작업이나 호스팅 설정은 저장소에서 확인되지 않습니다. Cloudflare, GitHub Pages, Vercel 배포 설정도 없습니다. GitHub Actions는 품질 검증만 하며 운영 배포를 수행하지 않습니다.

`npm run build -- --webpack`과 `npm run start`로 일반 Next.js 서버 빌드 및 실행은 가능하지만 실제 운영 호스트와 배포 절차는 정의되어 있지 않습니다.

## 운영 데이터 특성

사용자 데이터는 각 브라우저에 저장됩니다. 브라우저 데이터 삭제, 다른 기기 사용, 저장 공간 제한의 영향을 받으므로 사용자가 JSON 백업을 직접 보관해야 합니다.

## 운영 시 주의할 점

- 서버 백업이나 계정 동기화가 없습니다.
- YouTube 썸네일과 embed가 차단되면 미리보기 또는 재생이 표시되지 않을 수 있습니다.
- 새 스키마 도입 시 `vibe-learning:v1` 및 v1 백업 호환성을 검토해야 합니다.
- CI 통과를 배포 완료로 해석하면 안 됩니다.
