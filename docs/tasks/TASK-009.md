# TASK-009: TASK-007 결과서 정합성 보정 및 생성 파일 변경 정리

## 목표

TASK-007 구현 결과와 `docs/tasks/TASK-007-RESULT.md`의 기록을 실제 작업 트리 상태에 맞게 정리한다. 결과서의 오탈자와 모호한 검증 근거를 보정하고, TASK-007 범위에 포함되지 않은 `next-env.d.ts` 변경이 빌드·E2E 실행 중 생성된 부수 변경인지 확인한 뒤 안전하게 처리한다.

이번 작업은 TASK-007의 기능을 확장하는 작업이 아니다. 자동 제목 캐시, 상태 전이, YouTube 제목 Route Handler 및 저장 스키마의 동작은 변경하지 않는다.

## 현재 문제

### 1. 결과서와 실제 변경 파일 목록 불일치

`docs/tasks/TASK-007-RESULT.md`의 변경 파일 표에는 다음 파일만 기록되어 있다.

- `components/AddVideoForm.tsx`
- `components/AddVideoForm.test.tsx`
- `e2e/youtube-title.spec.ts`
- `docs/tasks/TASK-007-RESULT.md`

하지만 현재 작업 트리에는 `next-env.d.ts`도 수정된 상태다. 이 파일의 Next.js 생성 타입 참조가 `.next/dev`에서 `.next-e2e/dev`로 변경되어 있다. 결과서에 누락된 의도적 변경인지, E2E 실행 과정에서 생긴 부수 변경인지 확인해야 한다.

### 2. 결과서 문장 오탈자

완료조건 표와 실패 항목 설명에 다음 오탈자가 있다.

- `보존되는다` → `보존된다`
- `유지되는다` → `유지된다`
- `통과되는다` → `통과한다`
- `폰백` → `폴백`

### 3. API 호출 횟수 근거가 모호함

결과서의 `A -> B -> A 재선택 시 A 제목 복원 및 API 호출 2회 검증`은 A와 B를 합한 전체 호출 횟수인지, A에 대한 호출 횟수인지 바로 알기 어렵다.

TASK-007의 완료조건은 다음 두 사실을 구분해 증명해야 한다.

- A에 대한 API 요청은 최초 1회만 발생한다.
- A와 B를 합한 전체 요청은 2회이며, A 재선택 때 세 번째 요청은 발생하지 않는다.

## 작업 범위

### 포함

1. 현재 `git diff`와 TASK-007 관련 파일을 대조한다.
2. `next-env.d.ts` 변경의 발생 원인과 필요성을 확인한다.
3. 부수적으로 생성된 변경이면 TASK-007 이전 내용으로 복원한다.
4. 의도적으로 필요한 변경이면 이유와 영향을 결과서 변경 파일 표 및 남은 위험에 기록한다.
5. `TASK-007-RESULT.md`의 오탈자를 수정한다.
6. A → B → A 테스트의 API 호출 횟수 근거를 영상별·전체 횟수로 명확히 기록한다.
7. 최종 작업 트리와 결과서의 변경 파일 목록이 일치하는지 확인한다.
8. 정리 후 필수 회귀 검증을 다시 실행하고 실제 결과만 기록한다.

## 작업 절차

### 1. 사전 확인

다음 파일을 먼저 읽는다.

- `AGENTS.md`
- `docs/tasks/TASK-007.md`
- `docs/tasks/TASK-007-RESULT.md`
- `components/AddVideoForm.tsx`
- `components/AddVideoForm.test.tsx`
- `e2e/youtube-title.spec.ts`
- `next-env.d.ts`
- `playwright.config.ts`

그다음 `git status --short`와 관련 파일의 `git diff`를 확인한다. 기존 사용자 변경을 임의로 되돌리지 않는다.

### 2. `next-env.d.ts` 판정

다음 기준으로 처리한다.

- TASK-007 기능 또는 저장소의 정상적인 타입 검사에 `.next-e2e` 참조가 필요하지 않다면 생성 도구가 만든 부수 변경으로 판단하고 원래 `.next/dev` 참조로 복원한다.
- 프로젝트 설정상 `.next-e2e` 참조가 의도적으로 필요하다면 파일을 유지하되, 왜 필요한지와 일반 개발·빌드·E2E 각각에 미치는 영향을 결과서에 기록한다.
- 추측만으로 파일을 유지하거나 삭제하지 않는다. `playwright.config.ts`, Next.js 생성 동작, 실행 후 diff를 근거로 판단한다.
- 복원 후 검증 명령이 다시 파일을 변경한다면 어떤 명령에서 변경되는지 분리 실행해 확인하고 결과서에 기록한다.

### 3. 결과서 보정

`docs/tasks/TASK-007-RESULT.md`에서 다음을 반영한다.

- 확인된 오탈자 네 종류 수정
- API 호출 횟수를 `A 1회 + B 1회 = 전체 2회, A 재선택 추가 호출 0회`처럼 명확히 설명
- 최종 상태에 맞는 변경 파일 표 작성
- `next-env.d.ts`를 복원했다면 최종 변경 파일에서 제외하고 부수 변경을 정리했다는 사실을 필요한 경우 검증 참고에 기록
- `next-env.d.ts`를 유지한다면 변경 파일 표에 포함하고 변경 이유를 설명
- 실제로 다시 실행한 명령과 결과만 검증 결과에 기록

### 4. 회귀 검증

저장소 루트에서 다음 명령을 각각 실행한다.

```text
npm run lint
npm run typecheck
npm test
npm run build -- --webpack
npm run test:e2e
```

검증 전후로 `git status --short`와 `git diff -- next-env.d.ts`를 확인한다. 특정 명령이 `next-env.d.ts`를 다시 변경한다면 해당 명령과 변경 내용을 결과서에 남긴다.
