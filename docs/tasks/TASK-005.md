# TASK-005: external 모드 학습 중심 상세 화면 재배치

## 목표

`external` 재생 모드의 상세 화면에서 플레이어 또는 플레이어를 대신하는 큰 빈 공간을 제거하고, 사용자가 실제로 조작하는 **학습 구간**과 **개인 메모**를 화면의 중심에 배치한다.

- 외부 재생에 필요한 링크, 마지막 학습 위치, 모드 전환 기능은 유지하되 하나의 간결한 도구 모음으로 축소한다.
- 데스크톱에서는 학습 구간과 개인 메모를 나란히 보여 주어 영상은 YouTube에서 보고 기록은 앱에서 하는 흐름을 강화한다.
- 좁은 화면에서는 학습 구간 다음에 개인 메모가 이어지는 한 열 구조로 전환한다.
- `embedded` 모드의 플레이어 중심 레이아웃과 기존 저장 동작은 그대로 유지한다.

## 현재 문제

현재 상세 화면은 `components/LearningVideoDetail.tsx`와 `app/globals.css`에서 두 재생 모드를 같은 `player` 그리드 영역을 중심으로 구성한다.

- `embedded` 모드에서는 `YouTubeLearningPlayer`가 `player` 영역을 사용하는 것이 자연스럽다.
- `external` 모드에서는 iframe이 제거되지만, `.external-playback`이 `player` 영역 전체를 차지한다. 이 영역에는 `YouTube에서 보기`, 마지막 학습 위치 저장, `앱에서 재생 시도`만 있어 사용 면적에 비해 정보 밀도가 낮다.
- 학습 구간과 개인 메모는 큰 외부 재생 도구 아래에 각각 전체 너비로 쌓인다. 외부 모드의 핵심 작업임에도 첫 화면에서 밀리거나 서로 떨어져 보인다.
- `.external-detail-layout`이 플레이어가 없는 모드에도 `player`라는 그리드 영역 이름을 유지해 레이아웃 의도가 불명확하다.
- 데스크톱에서 개인 메모가 전체 너비가 되고 높이 제한도 해제되어, 구간과 메모를 함께 보며 기록하기 어렵다.
- 현재 E2E 테스트는 iframe 제거와 외부 기능 동작을 확인하지만, 플레이어 공간이 사라졌는지와 구간·메모가 주 작업 영역으로 재배치되었는지는 보장하지 않는다.

참고로 `docs/02_주요기능.md`의 재생 위치 설명 일부는 현재 코드보다 오래되었다. 구현 판단은 현재 코드와 테스트를 기준으로 하고, 이번 작업은 문서 전반의 현행화로 범위를 넓히지 않는다.

## 요구사항

### 1. external 모드 정보 구조

`external` 모드의 상세 화면 순서를 다음과 같이 구성한다.

```text
제목                                      학습 상태
저장 오류 또는 안내
외부 학습 도구 모음
┌──────────────────────────┬──────────────────────────┐
│ 학습 구간                │ 개인 메모                │
│ 구간 추가·목록·관리      │ 위치 표시·작성·목록·관리 │
└──────────────────────────┴──────────────────────────┘
영상 ID
```

- `.external-playback`을 플레이어 대체 패널로 취급하지 않는다. 이름을 포함한 구조와 스타일은 외부 학습용 도구 모음이라는 역할이 드러나게 정리한다.
- 도구 모음은 별도의 영상 비율, 고정 높이, 큰 플레이스홀더를 갖지 않는다.
- 도구 모음에는 다음 기존 기능을 모두 유지한다.
  - 저장된 `playbackSeconds`부터 여는 `YouTube에서 보기` 링크
  - YouTube가 새 탭에서 열린다는 안내
  - `분:초` 또는 `시:분:초` 형식의 마지막 학습 위치 입력과 저장
  - `앱에서 재생 시도`를 통한 `embedded` 모드 복귀
  - 입력 오류의 인접 표시 및 `role="alert"`
- 도구 모음은 데스크톱에서 한 줄 또는 내용에 맞는 조밀한 행으로 표현하되, 기능을 감추는 접기 UI는 추가하지 않는다.

### 2. 학습 구간과 개인 메모 중심 배치

- 901px 이상에서 외부 모드의 주 작업 영역을 두 열로 배치한다.
  - 왼쪽: `LearningSegments`
  - 오른쪽: 개인 메모 섹션
  - 권장 열 비율: `minmax(0, 1.15fr) minmax(320px, 0.85fr)` 또는 실제 내용 검증 후 이에 준하는 비율
- 두 섹션은 같은 행의 위쪽에서 시작한다. 한쪽 콘텐츠가 길어져도 다른 쪽에 불필요한 고정 높이나 빈 공간을 강제하지 않는다.
- 학습 구간의 제목, 추가 폼, 빈 상태, 목록, 수정·삭제, 외부 시작 링크를 모두 유지한다.
- 개인 메모의 현재 위치 표시, 작성 폼, 개수, 빈 상태, 목록, 수정·삭제, 타임스탬프 링크를 모두 유지한다.
- `external` 모드에서 개인 메모 목록에 플레이어 기준의 `max-height`를 다시 적용하지 않는다. 페이지 스크롤로 전체 기록에 접근할 수 있어야 한다.
- 두 열 내부의 폼과 긴 제목·메모가 열 너비를 밀어내지 않도록 `min-width: 0`, 줄바꿈 및 버튼 래핑을 보장한다.

### 3. 반응형 동작

- 900px 이하에서는 다음 순서의 한 열로 전환한다.
  1. 제목
  2. 오류 또는 안내
  3. 외부 학습 도구 모음
  4. 학습 구간
  5. 개인 메모
  6. 학습 상태
  7. 영상 ID
- 520px 이하에서는 외부 도구 모음의 링크, 시간 입력, 저장 버튼이 가로 폭을 넘지 않아야 한다. 필요한 경우 각 조작을 한 열로 쌓고 주요 버튼의 터치 영역을 최소 44px로 유지한다.
- 360px 뷰포트에서 문서 전체의 가로 스크롤이 없어야 한다.
- 모바일에서도 학습 구간을 개인 메모보다 먼저 배치한다.

### 4. 모드별 격리

- `external`일 때 `YouTubeLearningPlayer`, iframe, `.detail-player-column`, 플레이어용 종횡비 공간을 렌더링하지 않는다.
- `embedded` 모드의 현재 구조인 플레이어와 개인 메모의 데스크톱 두 열, 그 아래 학습 구간 배치는 변경하지 않는다.
- 모드 전환 후에도 기존 `playbackSeconds`, 학습 구간, 메모, 학습 상태가 보존되어야 한다.
- 레이아웃 분기는 `video.playbackMode`라는 기존 상태를 사용하며 별도의 중복 UI 상태를 저장하지 않는다.

### 5. 접근성과 링크 안전성

- 외부 도구 모음, 학습 구간, 개인 메모는 접근 가능한 영역 이름을 유지한다. 기존 테스트와 사용자 흐름을 위해 `외부 재생 도구`, `학습 구간`, `개인 메모`라는 이름은 가능하면 유지한다.
- 시각적 순서와 DOM 순서를 같게 한다. CSS만으로 읽기 순서를 뒤집지 않는다.
- 모든 입력은 연결된 레이블을 유지하고 키보드만으로 링크, 입력, 저장, 수정, 삭제, 모드 전환에 접근할 수 있어야 한다.
- 새 탭 YouTube 링크는 기존처럼 안전한 `target`과 `rel` 속성을 유지한다.
- 색상만으로 모드나 오류를 구분하지 않는다.

## 제약사항

- 이번 작업은 상세 화면의 `external` 모드 레이아웃 개선이다. 새로운 기능, 콘텐츠, 자동 수집, 서버 API, 데이터베이스, 인증, 외부 라이브러리를 추가하지 않는다.
- `vibe-learning:v1`의 저장 키와 `LearningVideo` 스키마를 변경하지 않는다. 마이그레이션을 만들지 않는다.
- `playbackMode`, `playbackSeconds`, `segments`, `notes`의 의미와 백업·복원 형식을 변경하지 않는다.
- 시간 파싱과 YouTube URL 생성은 `lib/youtube/youtubePlayback.ts`의 기존 함수를 사용한다.
- 학습 구간은 종료 시간이 시작 시간보다 커야 하며, 메모는 영상당 최대 500개·항목당 2,000자라는 현재 검증을 유지한다.
- 확인되지 않은 영상 메타데이터, 요약, 타임스탬프 또는 출처를 추가하지 않는다.
- 콘텐츠를 HTML, JSX 또는 외부 스크립트로 실행하지 않는다.
- 관련 없는 문서나 컴포넌트를 정리하는 리팩터링으로 범위를 넓히지 않는다.
- `AGENTS.md`의 저장소 지침을 따르고, 구현 전에 설치된 Next.js 버전에 관련된 `node_modules/next/dist/docs/` 문서를 확인한다.
- 코드 작성 시 TypeScript, 2칸 들여쓰기, 기존 명명 및 테스트 배치 규칙을 따른다.

## 테스트 조건

### 컴포넌트 테스트

`components/LearningVideoDetail.test.tsx`의 기존 외부 모드 테스트를 유지·보강한다.

- `embedded`에서 `external`로 전환하면 iframe과 `.detail-player-column`이 사라진다.
- 외부 도구 모음, 학습 구간, 개인 메모가 모두 렌더링된다.
- 외부 도구 모음이 플레이어 컨테이너 내부에 있지 않고, 학습 구간과 개인 메모가 동일한 외부 주 작업 컨테이너의 형제 영역으로 구성된다.
- 유효한 위치 `12:43` 저장 시 `playbackSeconds`가 `763`이 되고 `YouTube에서 보기` 링크에 `t=763s`가 반영된다.
- 잘못된 시간 입력은 저장되지 않고 인접 오류를 표시한다.
- 저장한 외부 위치가 새 메모의 `timestampSeconds`와 `마지막 위치 적용`의 기준이 된다.
- 메모 타임스탬프는 같은 시각의 YouTube 링크를 새 탭으로 연다.
- `앱에서 재생 시도` 후 내장 플레이어가 다시 나타나며 기존 데이터가 유지된다.
- 학습 구간과 메모의 기존 추가·수정·삭제 테스트가 계속 통과한다.

구조 테스트는 사용자 관점의 역할과 레이블을 우선 사용한다. 레이아웃 계약을 확인하는 데 꼭 필요한 최소한의 전용 클래스 또는 `data-*`만 검사하고, 세부 CSS 선언값 전체에 결합하지 않는다.

### E2E 테스트

`e2e/external-playback.spec.ts`와 `e2e/mobile.spec.ts`를 보강한다.

1. 영상을 등록하고 외부 모드로 전환한다.
2. iframe이 없고 외부 도구 모음, 학습 구간, 개인 메모가 보이는지 확인한다.
3. 위치를 저장하고 YouTube 보기 링크, 구간 시작 링크, 메모 타임스탬프에 올바른 초가 반영되는지 확인한다.
4. 구간과 메모를 추가·수정·삭제하고 새로고침 전후 저장 상태를 확인한다.
5. 1280px 이상의 뷰포트에서 학습 구간과 개인 메모의 상단 좌표가 같은 행에 있고, 학습 구간이 왼쪽에 있는지 검증한다.
6. 900px 이하에서 학습 구간이 개인 메모보다 위에 있는지 검증한다.
7. 360px에서 `scrollWidth <= clientWidth`이며 모든 외부 도구 조작과 구간·메모 조작이 화면 안에서 접근 가능한지 확인한다.
8. 내장 모드로 복귀해 플레이어가 다시 표시되고 기존 학습 데이터가 남아 있는지 확인한다.

새 탭 자체를 실제 YouTube 네트워크에 의존해 로드하지 않는다. 링크의 URL, `target`, `rel` 또는 `window.open` 호출을 검증한다.

5. 테스트를 먼저 보강해 다음 계약을 고정한다: 외부 모드에 플레이어 공간 없음, 도구 모음 유지, 데스크톱 두 열, 모바일 구간 우선 한 열, 기존 외부 동작 보존.
6. DOM을 외부 모드의 실제 읽기 순서에 맞게 구성한다. 그리드 영역 이름에서도 `player`를 재사용하지 말고 역할이 드러나는 이름을 사용한다.
7. 외부 도구 모음을 간결하게 스타일링하고 학습 구간·개인 메모를 묶는 외부 모드 전용 주 작업 레이아웃을 만든다. 불필요한 고정 높이와 플레이어 비율 규칙을 적용하지 않는다.
8. `embedded` 모드의 JSX와 스타일은 가능한 한 그대로 두고, 공용 선택자의 변경이 내장 모드에 영향을 주지 않도록 외부 모드 범위를 명시한다.
9. 저장 로직이나 스키마를 레이아웃 코드에 맞춰 변경하지 않는다. 기존 핸들러와 `createYouTubeWatchUrl`, `parseTimeInput`, `formatTimeInput`을 재사용한다.
10. 테스트에서 세부 구현 클래스에 과도하게 결합하지 않는다. 단, 두 열/한 열의 실제 시각 배치는 Playwright의 요소 위치 비교와 가로 오버플로 검사로 검증한다.
11. 1280px 이상, 900px 이하, 360px에서 직접 확인하고 긴 구간 제목, 긴 메모, 버튼 래핑, 오류 문구가 레이아웃을 깨지 않는지 점검한다.
12. 필수 회귀 명령을 모두 실행한다. 실패하면 수정 후 다시 실행하고, 환경 문제로 실행할 수 없는 항목은 결과에 명시한다.
13. 구현 완료 보고에는 변경 파일, 외부/내장 모드별 결과, 실행한 검증과 결과, 남은 위험만 간결하게 정리한다. 요청받지 않은 커밋이나 배포는 수행하지 않는다.
