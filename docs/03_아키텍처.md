# 아키텍처

## 전체 구조

```text
사용자
  ↓
Next.js App Router 화면
  ├─ 홈 /                  URL 등록, 목록, 백업·복원
  └─ 상세 /videos/[id]     플레이어, 상태, 개인 메모
  ├─ 클라이언트 → URL 파서 + Zod 데이터 검증 → IndexedDB (vibe-learning:v1)
  └─ GET /api/youtube-title → YouTube Data API videos.list (제목만 반환)
```

데이터베이스와 서버 저장은 없습니다. 사용자 데이터 읽기와 쓰기는 클라이언트 컴포넌트에서 IndexedDB를 통해 수행합니다. 제목 조회 Route Handler만 서버의 `YOUTUBE_API_KEY`로 고정된 YouTube Data API 엔드포인트를 호출하며, 키와 Google 원문 응답은 브라우저에 전달하지 않습니다.

## 데이터 흐름

- 등록: `URL 입력 → 파싱/정규화 → 제목 API 조회 또는 수동 입력 → 중복 검사 → Zod 검증 → IndexedDB 저장 → 상세 이동`
- 상세: `저장소 읽기 → 상태/메모 변경 → 전체 저장소 재검증 → 저장`
- 복원: `JSON 읽기 → v1 검증 → 미리보기 → 병합 또는 교체 → 저장`

저장 성공 후 `BroadcastChannel("vibe-learning:v1")`로 `learning-store-updated` 메시지를 발행합니다. 각 클라이언트 화면은 메시지를 받으면 IndexedDB를 다시 읽어 다른 탭의 변경을 반영합니다. BroadcastChannel을 지원하지 않는 환경에서는 noop으로 동작합니다.

## 정적 콘텐츠 경로

`content/first-video.json`과 `content/second-video.json`은 로더에서 가져온 뒤 Zod로 파싱됩니다. `/learn/[slug]`가 검수 콘텐츠를 읽어 `LearningWorkspace`에 전달하며, first-video와 second-video는 각각 3단계와 4단계로 렌더링됩니다.

## 외부 연결

런타임 외부 자원은 YouTube 썸네일(`i.ytimg.com`), 개인정보 강화 embed(`youtube-nocookie.com`), 공식 YouTube Data API의 `videos.list`(`www.googleapis.com`)입니다. Data API 호출은 서버 Route Handler에서 제목 필드만 요청합니다. OpenAI API는 사용하지 않습니다.
