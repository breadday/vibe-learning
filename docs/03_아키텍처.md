# 아키텍처

## 전체 구조

```text
사용자
  ↓
Next.js App Router 화면
  ├─ 홈 /                  URL 등록, 목록, 백업·복원
  └─ 상세 /videos/[id]     플레이어, 상태, 개인 메모
  ↓
클라이언트 컴포넌트
  ↓
URL 파서 + Zod 데이터 검증
  ↓
브라우저 localStorage (vibe-learning:v1)
```

서버 API와 데이터베이스는 없습니다. 페이지 틀은 Next.js가 렌더링하지만 사용자 데이터 읽기와 쓰기는 클라이언트 컴포넌트에서 수행합니다.

## 주요 모듈

| 위치 | 역할 |
|---|---|
| `app/page.tsx` | 홈 화면 구성 |
| `app/videos/[id]/page.tsx` | 영상 상세 진입점 |
| `components/AddVideoForm.tsx` | URL 검사, 등록, 중복 처리 |
| `components/LearningLibrary.tsx` | 목록 정렬·삭제 |
| `components/LearningVideoDetail.tsx` | 상태와 개인 메모 관리 |
| `components/BackupRestore.tsx` | JSON 백업·복원 UI |
| `lib/youtube/parseYouTubeUrl.ts` | 호스트와 영상 ID 검사 |
| `lib/storage/learningStore.ts` | 저장 스키마, 읽기·쓰기, 오류 처리 |
| `lib/storage/learningBackup.ts` | 백업 검증과 병합 |
| `lib/content/schema.ts` | 검수 콘텐츠와 구간 규칙 검증 |

## 데이터 흐름

- 등록: `URL 입력 → 파싱/정규화 → 중복 검사 → Zod 검증 → localStorage 저장 → 상세 이동`
- 상세: `저장소 읽기 → 상태/메모 변경 → 전체 저장소 재검증 → 저장`
- 복원: `JSON 읽기 → v1 검증 → 미리보기 → 병합 또는 교체 → 저장`

저장 후 사용자 정의 이벤트 `vibe-learning:store-changed`를 발생시켜 같은 탭의 목록을 갱신합니다. 다른 탭의 변경은 브라우저 `storage` 이벤트를 구독합니다.

## 정적 콘텐츠 경로

`content/first-video.json`은 `lib/content/first-video.ts`에서 가져온 뒤 Zod로 파싱됩니다. `LearningWorkspace`가 이 형식을 소비할 수 있지만 현재 `app/` 라우트에서는 사용하지 않습니다. `content/reviewed/first-video.mdx`도 현재 라우트에 직접 연결되어 있지 않습니다.

## 외부 연결

런타임 외부 자원은 YouTube 썸네일(`i.ytimg.com`)과 개인정보 강화 embed(`youtube-nocookie.com`)입니다. YouTube API나 OpenAI API를 호출하는 코드는 없습니다.
