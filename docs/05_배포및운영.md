# 배포 및 운영

## 현재 확인된 자동화

`.github/workflows/ci.yml`의 GitHub Actions `Verify` 워크플로는 Pull Request와 `main` 브랜치 push 때 다음을 실행합니다.

```text
checkout → Node.js 24 → npm ci → lint → typecheck → Vitest
→ webpack 프로덕션 빌드 → Playwright Chromium 설치 → E2E 테스트
```

같은 Git ref의 새 실행이 시작되면 이전 실행을 취소하고, 작업 제한 시간은 10분입니다.

## 실제 배포 방식 (Vercel)

- 프로덕션 URL: https://vibe-learning-blush.vercel.app/
- 호스팅: Vercel
- 배포 방법: Vercel 대시보드에서 New Project → GitHub 저장소 import
- 빌드 명령: `npm run build -- --webpack`
- 배포 트리거: GitHub 연동으로 `main` 브랜치 push 시 자동 배포 (Vercel 기본 설정)
- 빌드/도메인/Analytics 등 세부 설정은 Vercel 대시보드에서 관리

### 모니터링

- `@vercel/analytics`의 `<Analytics />`를 루트 레이아웃에서 활성화했다.
- `next/web-vitals`의 `useReportWebVitals`를 `components/WebVitals.tsx`에 연결했다.
- 측정 리포터는 개발 환경에서 Web Vitals 값을 콘솔에 출력하며, 운영 수집은 Vercel Analytics가 담당한다.
- 실제 대시보드 데이터와 Lighthouse 점수는 배포 환경에서 별도 확인해야 한다.

## 운영 데이터 특성

사용자 데이터는 각 브라우저에 저장됩니다. 브라우저 데이터 삭제, 다른 기기 사용, 저장 공간 제한의 영향을 받으므로 사용자가 JSON 백업을 직접 보관해야 합니다.

## 운영 시 주의할 점

- 서버 백업이나 계정 동기화가 없습니다.
- YouTube 썸네일과 embed가 차단되면 미리보기 또는 재생이 표시되지 않을 수 있습니다.
- 새 스키마 도입 시 `vibe-learning:v1` 및 v1 백업 호환성을 검토해야 합니다.
- CI 통과만으로 배포 상태나 Analytics 데이터 수집을 보장하지 않으므로 Vercel 대시보드에서 별도 확인합니다.
