# TASK-006: YouTube 학습 제목 자동 입력

## 목표

사용자가 유효한 YouTube 주소를 입력하면 공식 YouTube Data API로 영상 제목을 조회해 `학습 제목` 입력란에 자동으로 채운다.

- 주소 입력만으로 등록 준비가 빠르게 끝나도록 한다.
- 자동 입력된 제목은 사용자가 자유롭게 수정할 수 있게 한다.
- API 조회 실패가 기존 수동 등록 기능을 막지 않게 한다.
- YouTube API 키를 브라우저와 저장 데이터에 노출하지 않는다.

## 현재 문제

- `components/AddVideoForm.tsx`는 URL을 파싱해 영상 ID와 썸네일을 즉시 보여 주지만, 제목은 항상 사용자가 직접 입력해야 한다.
- `docs/02_주요기능.md`와 `docs/13_youtube_url_learning_design.md`는 외부 API로 제목을 자동 조회하지 않는 것을 현재 범위로 명시한다.
- 프로젝트에는 서버 API 경로와 YouTube API 키 설정이 없다.
- 자동 조회를 단순히 추가하면 늦게 도착한 응답이 사용자가 입력한 제목을 덮어쓰거나, URL을 빠르게 바꿨을 때 이전 영상 제목이 표시될 수 있다.
- 클라이언트에서 YouTube Data API를 직접 호출하면 API 키가 브라우저 번들 또는 네트워크 요청에 노출된다.

## 요구사항

### 1. 공식 YouTube Data API 사용

- 공식 `videos.list` 엔드포인트를 사용한다.
- 요청 대상은 고정된 `https://www.googleapis.com/youtube/v3/videos`로 제한한다.
- `part=snippet`, 검증된 11자리 `id`, 서버 환경변수의 API 키를 사용한다.
- 응답에서 등록 폼에 필요한 `items[0].snippet.title`만 추출한다. 설명, 태그, 통계 등 불필요한 데이터는 클라이언트에 반환하지 않는다.
- 가능하면 `fields=items(snippet(title))`를 사용해 응답 범위를 줄인다.
- 영상 HTML을 스크래핑하거나 비공식 메타데이터 서비스를 사용하지 않는다.

### 2. 서버 Route Handler

- `app/api/youtube-title/route.ts`에 `GET` Route Handler를 둔다.
- 요청 형식은 `/api/youtube-title?videoId={11자리 ID}`로 한다.
- 서버에서도 영상 ID를 `/^[A-Za-z0-9_-]{11}$/`로 다시 검증한다. 클라이언트 검증만 신뢰하지 않는다.
- API 키 환경변수 이름은 `YOUTUBE_API_KEY`로 한다.
- `NEXT_PUBLIC_` 접두사를 사용하지 않고 `process.env.YOUTUBE_API_KEY`는 Route Handler 또는 서버 전용 모듈에서만 읽는다.
- 정상 응답은 `{ "title": "영상 제목" }` 형태로 제한한다.
- 다음 실패를 구분하되 API 키, Google 원문 응답, 내부 상세정보는 클라이언트에 노출하지 않는다.
  - `400`: 유효하지 않은 영상 ID
  - `404`: 조회 결과가 없거나 사용할 수 없는 영상
  - `502`: YouTube API 오류 또는 해석할 수 없는 응답
  - `503`: 서버에 API 키가 설정되지 않음
- Route Handler는 사용자 입력을 외부 URL이나 호스트로 사용하지 않는다. 영상 ID만 고정된 Google API 요청의 쿼리 값으로 전달한다.

### 3. 자동 제목 입력 흐름

- URL 파서가 유효한 새로운 `videoId`를 반환하면 제목 조회를 시작한다.
- 주소 입력 중 매 키 입력마다 요청하지 않는다. 유효한 ID가 확정된 뒤 짧은 디바운스 또는 붙여넣기 완료 시점에 영상 ID당 한 번만 요청한다.
- 조회 중에는 제목 입력란 가까이에 `영상 제목을 가져오는 중입니다.` 상태를 표시한다.
- 조회 성공 시 사용자가 제목을 직접 입력하거나 수정하지 않은 경우에만 자동 제목을 입력한다.
- 자동 입력 후에도 제목 입력란은 활성 상태이며 사용자가 내용을 수정할 수 있다.
- 사용자가 입력을 시작한 이후 도착한 API 응답은 제목을 덮어쓰지 않는다.
- URL이 다른 유효한 영상으로 변경되면 이전 요청을 취소하거나 응답 식별자를 비교해 이전 영상의 응답을 무시한다.
- 이전 영상에서 자동 입력된 제목만 남아 있는 상태로 URL이 변경되면 이전 자동 제목을 지우고 새 제목을 조회한다.
- 사용자가 직접 작성한 제목은 URL 변경이나 조회 실패로 자동 삭제하지 않는다.
- URL이 비어 있거나 유효하지 않으면 제목 조회를 수행하지 않는다.

### 4. 실패와 수동 입력 폴백

- 제목 조회 실패는 등록을 차단하는 치명적 오류로 취급하지 않는다.
- 실패 시 `제목을 자동으로 가져오지 못했습니다. 직접 입력해 주세요.`라는 간결한 안내를 제목 입력란 가까이에 표시한다.
- 사용자는 실패 후에도 제목을 입력하고 기존 방식으로 영상을 등록할 수 있다.
- 조회 실패 상태에서 자동 재시도를 반복하지 않는다. URL이 바뀌면 새 영상에 대해 다시 시도할 수 있다.
- API 키 미설정, 할당량 초과, 네트워크 오류의 내부 원인을 일반 사용자에게 구체적으로 노출하지 않는다. 개발 로그에도 API 키를 기록하지 않는다.
- 자동 입력된 제목이 빈 문자열이거나 100자를 초과하거나 예상 타입이 아니면 성공으로 처리하지 않는다.

### 5. 중복과 저장 동작

- 기존 `학습에 추가` 조건인 유효한 URL과 비어 있지 않은 제목을 유지한다.
- 자동 제목도 사용자가 입력한 제목과 동일하게 trim한 뒤 기존 `LearningVideo.title`에 저장한다.
- `vibe-learning:v1` 저장 스키마, 백업 형식, 중복 영상 처리와 상세 화면 이동을 변경하지 않는다.
- 중복 영상은 새 항목을 만들지 않고 기존 영상 이동 안내를 유지한다.
- 제목의 출처나 API 응답 전체를 `localStorage`에 추가로 저장하지 않는다.

### 6. 설정과 운영 안내

- 로컬 실행에는 Google Cloud 프로젝트에서 YouTube Data API v3를 활성화하고 발급한 API 키가 필요하다.
- 실제 키는 Git에 커밋하지 않는다. 저장소의 `.gitignore`에 포함된 `.env*` 정책을 유지한다.
- 설정 문서에는 `YOUTUBE_API_KEY`라는 변수 이름과 설정 필요성만 기록하고 실제 값을 예시로 넣지 않는다.
- API 키에는 YouTube Data API만 호출할 수 있도록 API 제한을 적용하도록 안내한다.
- 현재 프로젝트는 개인·로컬 우선이므로 공개 배포 시 무인증 Route Handler가 할당량 남용 경로가 될 수 있음을 문서화한다. 공개 배포 전에 요청 제한 또는 배포 환경에 맞는 키 제한을 별도 검토한다.

## 제약사항

- YouTube Data API 사용 결정 외에는 v0.1 범위를 서버 저장, 로그인, 데이터베이스, AI, 자막 수집으로 넓히지 않는다.
- API 키를 클라이언트 컴포넌트, `NEXT_PUBLIC_*`, 응답 본문, 오류 메시지, 로그, 테스트 스냅샷에 포함하지 않는다.
- `.env`, `.env.local` 등 실제 환경변수 파일을 생성하거나 커밋하지 않는다.
- 새로운 npm 패키지를 추가하지 않고 표준 `fetch`, `Request`, `Response`, React API를 사용한다.
- 영상 제목 외의 채널, 게시일, 설명, 자막, 재생 시간은 이번 작업에서 자동 수집하지 않는다.
- 자동 제목을 검수된 학습 콘텐츠의 메타데이터로 간주하지 않는다.
- API 실패 시 확인되지 않은 제목을 생성하거나 영상 ID를 제목으로 자동 저장하지 않는다.
- 현재 제목 입력의 `maxLength=120`과 저장 스키마는 유지하되, YouTube API 제목은 공식 최대 길이인 100자 이내인지 검증한다.
- 사용자의 기존 작업과 TASK-005 변경을 덮어쓰거나 되돌리지 않는다.
- 구현 전에 설치된 Next.js 16 문서의 Route Handler와 환경변수 지침을 다시 확인한다.

## 테스트 조건

### Route Handler 테스트

- 유효한 ID와 정상 YouTube 응답에서 제목만 반환
- 잘못된 ID에서 외부 요청 없이 `400`
- `items`가 빈 응답에서 `404`
- API 키 미설정에서 외부 요청 없이 `503`
- Google의 비정상 상태 또는 잘못된 JSON에서 안전한 `502`
- API 응답이나 오류 응답에 API 키와 불필요한 메타데이터가 포함되지 않음
- Google 요청이 고정 호스트, `part=snippet`, `fields`, 검증된 `id`를 사용함

외부 YouTube API를 실제 호출하지 말고 `fetch`를 모킹해 결과가 네트워크와 할당량에 의존하지 않게 한다.

### 컴포넌트 테스트

- 유효 URL 입력 시 로딩 상태 표시 후 자동 제목 입력
- 자동 제목으로 등록 버튼 활성화
- 자동 입력된 제목을 수정한 값으로 저장
- 요청 중 사용자가 제목을 입력하면 응답이 도착해도 사용자 값 유지
- URL A 요청 후 URL B로 변경했을 때 A 응답 무시
- 자동 제목 상태에서 URL 변경 시 이전 자동 제목 제거
- 직접 입력한 제목은 URL 변경 시 보존
- 실패 안내 후 수동 입력과 등록 가능
- 빈 URL과 잘못된 URL에서는 `fetch`가 호출되지 않음
- 컴포넌트 해제 시 완료된 비동기 응답으로 상태를 변경하지 않음
- 중복 영상 처리와 저장 실패 메시지 회귀 없음

### E2E 테스트

- 내부 제목 API 응답을 Playwright에서 가로채 고정된 제목을 반환한다. 실제 Google API와 실제 키에 의존하지 않는다.
- URL 붙여넣기 후 자동 제목이 표시되고 수정 없이 등록되는 흐름을 검증한다.
- 자동 제목을 사용자가 수정해 수정된 제목이 상세·목록·새로고침 후 유지되는지 검증한다.
- API 실패 응답 후 수동 제목으로 등록되는 흐름을 검증한다.
- 360px에서 로딩·실패 안내와 제목 입력이 가로 오버플로를 만들지 않는지 확인한다.

### 필수 회귀 검증

저장소 루트에서 다음 명령을 각각 실행하고 실제 결과를 결과서에 기록한다.

```text
npm run lint
npm run typecheck
npm test
npm run build -- --webpack
npm run test:e2e
```

실제 API 키 없이도 테스트와 빌드가 성공해야 한다. 실행하지 못했거나 실패한 검증은 통과했다고 기록하지 않는다.
